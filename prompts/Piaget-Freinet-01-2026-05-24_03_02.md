Você é um arquiteto sênior de compiladores, DX tooling, TUI/CLI design, sistemas agentic, DSLs, scaffolding engines, repositórios colaborativos e geração de software por especificação.

Sua tarefa é implementar uma ferramenta chamada, provisoriamente:

ABDD Builder

ou:

AtomicBehavior-Driven Development Builder

Objetivo da ferramenta:

Criar uma ferramenta interativa que questiona o desenvolvedor passo a passo, consulta um Repositório Universal de Semantic AtomicBehaviors, SemanticTypes, Entities, Properties, Refutations, Events e Tests já existentes, reaproveita automaticamente tudo que já existir, armazena as decisões do desenvolvedor e, ao final, gera arquivos `.um` estruturados:

- 1 arquivo `.um` para cada Entity;
- 1 arquivo `.um` para cada Property;
- 1 arquivo `.test.um` com os testes/refutações/oráculos derivados;
- 1 arquivo de configuração do projeto;
- 1 manifest com todos os artefatos reutilizados, novos ou pendentes.

Depois da geração dos arquivos `.um`, a ferramenta deve perguntar qual `mode` o dev deseja usar para projetar a arquitetura final.

Modes obrigatórios:

- `beginner`
- `state-of-the-art`

A ferramenta deve explicar pedagogicamente que o dev iniciante, ou o dev avaliando a ferramenta pela primeira vez, deve escolher exatamente a linguagem, framework, banco e arquitetura que ele já usa no dia a dia, para conseguir ler, auditar e avaliar o código gerado.

A mensagem obrigatória deve ser algo nesta linha:

“Para começar, escolha o framework, a linguagem e a arquitetura que você já domina. A ideia é você conseguir avaliar o código gerado sem precisar aprender uma arquitetura nova ao mesmo tempo. Quando quiser migrar para o modo state-of-the-art, você não precisa alterar nenhuma linha do código semântico. Basta mudar `mode = state-of-the-art` na configuração e rodar `make` na pasta do projeto. O compilador irá reprojetar o mesmo grafo de AtomicBehaviors para a arquitetura avançada.”

Conceito central:

O dev não deve começar escrevendo código.

A ferramenta deve ser interativa, educativa e orientada a descoberta.

Ela não deve apenas perguntar “digite entidades”. Ela deve sugerir opções existentes.

entity User {
  canonical_label "user"
  domain "commerce"

  property email uses UserEmail
  property cpf uses UserCPF
  property phone uses UserPhone

  behavior ValidateUserIdentity

  emits User.identity.validated

Gere 1 arquivo por propriedade:

Exemplo:

property User.cpf {
  canonical_label "user.cpf"
  semantic_type UserCPF
  primitive_envelope Word(Number)

  required true

  normalizer ExtractDigitsFromCPF
  validator ValidateCPFLength
  validator RefuteRepeatedDigits
  validator ValidateCPFChecksumDigit1
  validator ValidateCPFChecksumDigit2

  refutation EmptyCPF
  refutation InsufficientDigits
  refutation InvalidCPFLength
  refutation RepeatedCPFSequence
  refutation InvalidCPFChecksum

  event UserCPF.success
  event UserCPF.error
  event UserCPF.healed

  test_oracle UserCPFTestOracle

Mode selection:

Depois de gerar os `.um`, a ferramenta deve mostrar:

“Agora escolha o modo de projeção arquitetural.”

Mostrar:

1. Beginner Mode
2. State-of-the-Art Mode

Beginner Mode deve ser explicado assim:

Beginner Mode gera um sistema usando a stack que você já conhece. Ele é ideal para avaliar a qualidade do código gerado, entender a estrutura, rodar localmente, debugar facilmente e entregar um MVP. Escolha a linguagem, framework, banco e arquitetura que você já usa no trabalho.

State-of-the-Art Mode deve ser explicado assim:

State-of-the-Art Mode projeta o mesmo grafo semântico para uma arquitetura avançada, multi-plane, event-sourced, observável, policromática, autopoiética e sintrópica. Ele usa tecnologias diferentes para funções diferentes e bancos diferentes para visões diferentes da entidade. Você não precisa alterar nenhuma linha dos arquivos `.um`: basta mudar `mode` na configuração e rodar `make`.

A ferramenta deve recomendar:

“Para sua primeira geração, escolha Beginner Mode com a stack que você já domina. Depois, quando confiar no código semântico gerado, mude para State-of-the-Art Mode apenas alterando a config.”

Requisito fundamental:

Nenhuma linha de código de domínio deve ser alterada para mudar de beginner para state-of-the-art.

A troca deve ser feita apenas por configuração:

mode = beginner

para:

mode = state-of-the-art

e depois:

make generate
make test
make run

A ferramenta deve garantir que:

- os `.um` são a fonte da verdade;
- o código gerado é descartável/regenerável;
- a arquitetura é uma projeção;
- o comportamento semântico não depende do framework;
- os testes são derivados dos Semantic AtomicBehaviors;
- os imports são gerados automaticamente;
- o dev não precisa escrever imports manualmente;
- o reuso é automático e transparente.

Validação:

Implemente validações obrigatórias:

- entity names em PascalCase;
- property names em camelCase;
- canonical labels em lowercase dot notation;
- cada property deve ter SemanticType;
- cada SemanticType deve ter primitive envelope;
- cada property deve ter ao menos um behavior ou justification;
- cada refutation deve ter teste negativo;
- cada success event deve ter teste positivo;
- cada generated artifact deve ter version;
- nenhum arquivo `.um` pode referenciar artefato inexistente sem registrar unresolved artifact;
- `state-of-the-art` só pode ser gerado se o grafo semântico estiver válido.

Jean Piaget (1896–1980)
A Abordagem: Construtivismo.

A Inovação: Piaget provou que as crianças não são "adultos em miniatura" com menos conhecimento, mas sim indivíduos que pensam de forma qualitativamente diferente. Ele mapeou os estágios do desenvolvimento cognitivo.
